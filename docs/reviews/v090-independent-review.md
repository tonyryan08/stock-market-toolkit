## Verdict

**Ship with changes.** The rule is Carver's: every constant (16/64, λ = 2/(span+1), vol span 35, scalar 3.75, cap ±20, 256 days → ×16) matches `pysystemtrade`, the departures are stated, the arithmetic in the tests is right to six decimals by two independent recomputations, the VC-19 spreadsheet recipe reproduces the API's last row exactly, the routes, the migration and the receipt work, and the record is honest and almost entirely accurate. It can be taught.

**Must fix before the apply (2):** the nightly pass has no error handling per instrument — one bad instrument or one transient D1 error throws out of `runSignals`, and because the pass runs first in the 22:50 invocation the night's accounts refresh is lost with no receipt (reproduced locally); and the lesson's class exercise uses the 365-row default CSV while promising a fourth-decimal match — the slow EWMA differs at the fourth decimal in about half of all series at 365 rows (the VC-19 recipe, at 1,900 rows, is fine).

**Should fix, next shipment (10)** — the signals pass in its own cron invocation (CPU and resilience); the advice net's hyphen false positives and its stated reach; the number check's sign-blindness; the quote cap failing open on a D1 error; `npm audit fix` for a hono advisory; two slide corrections (Odean's sample; "Carver's rule … a century"); the by-hand λ rounding; the VC-19 troubleshooting line; the "fourth decimal / immaterial" claim about the zero-mean variance. **Notes (14).**
